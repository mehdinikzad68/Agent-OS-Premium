# ADR-002: Canonical repository — WSL Agent-OS, not the Windows copy

- **وضعیت:** پذیرفته‌شده (Accepted)
- **تاریخ:** ۲۰۲۶-۱۰-۰۶
- **تصمیم‌گیرنده:** مالک محصول (انسان)

## زمینه

دو کپی از پروژه روی این ماشین وجود دارد:

| مسیر | وضعیت |
|---|---|
| `/home/mehdi/workspace/Agent-OS` (WSL2, Ubuntu-26.04) | **رسمی** — ۴۲ کامیت، شاخهٔ `main` در `4783c9b` |
| `D:\DEV-Studio\Programming\Agent-OS` (Windows) | **غیررسمی و قدیمی** — ۶ کامیت، هیچ object مشترکی با کپی WSL ندارد |

این دو مخزن غریب (unrelated) هستند: `git` آن‌ها را به‌عنوان دو تاریخچهٔ
مستقل می‌بیند، نه دو شاخه از یک پروژه. هیچ روابط commit-ancestor یا
shared-object‌ای وجود ندارد، پس هیچ merge/rebase معناداری بینشان ممکن نیست.

این تفاوت در گذشته باعث خطاهای عملیاتی شده است. `git status` در مسیر
اشتباه چیز کاملاً متفاوتی نشان می‌دهد، و مسیرهای داخل کد و اسناد که به
`/home/mehdi/...` اشاره دارند در کپی Windows بی‌معنا هستند. به‌علاوه، این
مسیرها یک تلهٔ امنیتی هم دارند: هیچ agent نباید بدون اطلاع کاربر بین آن‌ها
داده جابه‌جا کند.

## تصمیم

**تنها مخزن رسمی پروژه `/home/mehdi/workspace/Agent-OS` در WSL است.** کپی
`D:\DEV-Studio\Programming\Agent-OS` یک کپی قدیمی و غیرمرجع است. هیچ agent یا
توسعه‌دهنده‌ای نباید در آن مسیر کار کند، فایل‌هایش را بخواند به‌عنوان
منبع حقیقت، یا چیزی در آن بنویسد.

## نحوهٔ اعتبارسنجی هرگاه مسیر محل کار نامطمئن است

دستور رسمی برای یافتن ریشهٔ مخزن:

```bash
git rev-parse --show-toplevel
```

اگر این دستور مسیری غیر از `/home/mehdi/workspace/Agent-OS` را برگرداند، شما
در مخزن اشتباه هستید. در کنارش، مسیر مطلق باید مستقیماً بررسی شود:

```bash
test "$(pwd)" = /home/mehdi/workspace/Agent-OS
```

دستور اول کافی نیست، چون ممکن است داخل یک subdirectory از مخزن رسمی باشید و
top-level چیز دیگری به نظر برسد (یا اصلاً در یک مخزن نباشید). این دو را
با هم استفاده کنید. اگر هر دو درست نبودند، هیچ تغییری نباید انجام شود.

در این harness، `pwd` به‌صورت پیش‌فرض به مسیر Windows اشاره می‌کند؛ این
یعنی **هر دستور git که بدون صریح‌سازی مسیر اجرا شود، روی مخزن اشتباه
اجرایی می‌شود.** بنابراین قبل از هر چیز باید مطمئن شد دستور در مسیر WSL
اجرا می‌شود (مثلاً از طریق `wsl -d Ubuntu-26.04` یا مسیر UNC).

## دلایل

1. **تاریخچه.** کپی WSL ۴۲ کامیت دارد؛ کپی Windows ۶ کامیت بدون ارتباط.
2. **حقیقت واحد.** وقتی دو کپی غریب وجود دارد، هر کدام «حقیقت» متفاوتی
   دارند. بدون این ADR، یک reader نمی‌تواند بداند کدام را باید باور کند.
3. **جلوگیری از خطای انسانی.** کار کردن در مسیر اشتباه، به‌طور خاموش،
   تغییراتی تولید می‌کند که در مخزن رسمی هرگز دیده نمی‌شوند.
4. **حریم خصوصی.** هیچ agent نباید محتوای پروژه را بین مخزن‌ها یا به یک
   سرویس خارجی جابه‌جا کند بدون اجازهٔ صریح.

## عواقب

- **هیچ sync خودکار نیست.** این ADR هیچ همگام‌سازی، merge یا push‌ای بین
  دو کپی ایجاد نمی‌کند. آن‌ها دو موجودیت جداگانه باقی می‌مانند.
- **هرگز در مسیر Windows کاری انجام نمی‌شود.** این یک قانون سخت است، نه
  یک توصیه.
- **هر سند یا دستوری که به پروژه اشاره دارد** باید مسیر WSL را به‌عنوان
  مسیر رسمی استفاده کند.
- **اسناد قدیمی که به مسیر Windows اشاره دارند** باید به‌عنوان قدیمی
  شناخته شوند، نه به‌عنوان جایگزین.
